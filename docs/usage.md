# Tatamiでメモを書き、Webサイトを作る

Tatamiは、Markdownを編集して、公開対象のメモを静的HTMLに変換するデスクトップアプリです。このガイド自身もTatamiでビルドできます。

## 1. 起動する

.NET 10 SDKを用意し、リポジトリで次を実行します。

```sh
cd /path/to/tatami
dotnet run --project Tatami.csproj
```

## 2. メモとHTMLの保存場所を別々に選ぶ

左側の「メモのディレクトリ…」からMarkdownを保存したフォルダを選びます。「HTML出力先…」から、生成するHTMLを置く別のフォルダを選びます。初回の出力先は空のフォルダを推奨します。

```text
workspace/
├── notes/          ← メモのディレクトリ
│   └── usage.md
└── site-output/    ← HTML出力先
    ├── tatami-guide/
    │   └── index.html
    └── style.css
```

2つの設定は個別に変更でき、アプリを再起動しても記憶されます。メモのフォルダを変えても出力先は自動変更されません。ビルド前に左側の表示を確認してください。

設定はOSのユーザー別アプリデータ領域にある `Tatami/workspace.json` にJSONで保存されます。メモのファイルには設定を書き込みません。出力先にメモと同じ場所やその親は指定できません。

## 3. Markdownを編集・保存する

左側の一覧から `.md` ファイルを選び、右側で編集します。行番号、Markdownの簡易色分け、折り返しに対応しています。

| 操作 | macOS | Windows / Linux |
| --- | --- | --- |
| 保存 | ⌘S | Ctrl+S |
| 検索 | ⌘F | Ctrl+F |
| 元に戻す | ⌘Z | Ctrl+Z |

未保存の変更はタブとタイトルの「●」で表示します。ファイルやメモのフォルダを切り替えるとき、または終了するときは、保存・破棄・キャンセルを選べます。外部アプリで同じファイルが変更された場合は、上書きせず下のパネルにエラーを表示します。

下部パネルには保存結果、ビルド結果、エラーを表示します。ペインの境界はドラッグで調整できます。一覧の「↻」はディスク上のファイル一覧を更新します。

## ノートの作成・名前変更・ゴミ箱

- 左側の「＋ 新規」（⌘N / Ctrl+N）で、選択フォルダにMarkdownを作成します。ファイル選択中はその親フォルダに作成します。新規ノートは `publish: false` です。
- 「名前変更」は編集中のファイル名を変更します。未保存の本文とUndo履歴を保持し、同名ファイルは上書きしません。
- 「ゴミ箱へ」で編集中のノートを移動します。未保存の場合は保存・破棄・キャンセルを選びます。
- 「復元」から元の場所に戻せます。同名ファイルがある場合は上書きせず中止するので、既存ファイルを名前変更してから復元してください。

ゴミ箱はOSのゴミ箱とは別の、メモフォルダ内の `.tatami-trash/` です。一覧とビルド対象から除外します。完全削除機能はありません。リポジトリのGit除外設定に追加済みですが、別のGit管理メモフォルダでも `.tatami-trash/` を除外してください。公開済みHTMLから記事を取り除くには、移動後に再ビルドを成功させてください。

## 4. 公開するメモを指定する

メモの先頭にYAML Front Matterを書きます。

```markdown
---
title: はじめての記事
date: 2026-11-22
tags: [日記, Tatami]
publish: true
slug: first-post
---

# 今日のこと

この段落は公開されます。
```

**ノート全体は `publish: true` の場合だけ公開します。** `publish: false`、指定なし、Front Matterなしのノートは非公開です。

`slug` はURLの識別子です。未指定ならファイル名から生成します。日本語・数字・ハイフン・アンダースコアを使えます。同じslugがある場合や、不正なパスを含む場合はビルドエラーになります。

## 5. 一部の文章・段落だけを公開しない

公開対象ノートの本文は、デフォルトですべてHTMLに含まれます。公開したくない段落は、独立した行の `:::private` と `:::` で囲みます。

```markdown
この文章は公開されます。

:::private
これは自分専用のメモです。

複数の段落や箇条書きもまとめて除外できます。
- 公開前の確認事項
- 内部用の補足
:::

この文章も公開されます。
```

囲まれた文章は元のMarkdownには残りますが、HTMLのソースにもコメントにも出力しません。閉じる `:::` を忘れるとビルドエラーになります。囲みは行単位の段落用です。文章の途中だけを除く場合は、その文章を独立した段落にしてください。

コードブロック内に書いた記法の説明は除外されません。このページの上のサンプルも、そのためHTMLに表示されます。非公開ノートの公開条件を変更する機能ではありません。

:::private
TATAMI_PRIVATE_DEMO_DO_NOT_EXPORT
この実例の段落はMarkdownにだけ残り、ビルド後のHTMLには含まれません。
:::

この行は非公開ブロックの後にあるため、HTMLにも表示されます。

## 6. ビルドしてアプリ内で見る

1. 左側のメモの場所とHTML出力先を確認します。
2. 「▷ サイトをビルド」を押します。
3. 現在の編集バッファを保存した後、公開ノートのHTMLとCSSを生成します。
4. 成功するとアプリ内のHTMLプレビューへ切り替わります。
5. 上部の選択欄で生成した記事を切り替えられます。
6. 「編集 / HTML」でエディタに戻れます。

プレビューは**最後にビルドしたHTML**を表示します。編集内容を反映するには再ビルドしてください。プレビューの「↻」は保存済みのHTMLを読み直す操作で、Markdownの再ビルドは行いません。

アプリ内プレビューでは出力先のHTMLを表示します。外部サイトや出力先以外への移動は制限しています。HTML自体は通常のブラウザでも開けます。内蔵ビルダーのCSSは相対パス参照なので、ローカルファイルとして開けます。外部ビルダーについては後述のHTTPプレビューを使用してください。

## 7. 生成物と安全な更新

出力先の `.tatami-manifest.json` は生成ファイルの管理に使います。削除・編集しないでください。Tatamiは出力先全体を消さず、自分が生成したファイルだけを更新します。公開を解除した記事のHTMLは、次回の成功したビルドで削除されます。

手動編集された生成物や同名の別ファイルがある場合は、上書きせず停止します。失敗したビルドでは以前の公開HTMLが残ることがあるため、非公開化のときもビルド成功を確認してください。

Gitで管理する場合は、出力フォルダを `.gitignore` に追加してください。リポジトリ直下の `site-output/` はすでに除外されています。

## 現時点の範囲

- 編集バッファは1ファイルです。複数タブは未実装です。
- 画像記法は使えますが、添付ファイルの自動コピーやリンクの自動書き換えはありません。
- 生HTMLは無効化しています。
- 記事一覧、タグページ、RSS、内部リンク変換、自動デプロイは未実装です。
- プレビューにはOSのWebViewを利用します。WindowsではWebView2、Linuxでは対応するWebKit環境が必要です。macOSでは標準のWebKitを利用します。
- 強制終了や電源断に対するサイト全体の完全なトランザクションはありません。同じ出力先を複数のプロセスから同時に変更しないでください。

## 8. Astroなど好きなビルダーを使う

左側の「ビルダー設定…」から「Tatami 内蔵」または「外部コマンド」を選べます。既存の設定は内蔵ビルダーとして読み込まれます。切り替えてもメモのディレクトリとHTML出力先は維持します。

### Astroのサンプルを使う

Node.js 22.23.4以上を用意し、付属サンプルの依存関係を準備します。

```sh
cd /path/to/tatami/examples/astro
npm ci
```

ビルダー設定で「Astroの実行設定を入力」を押し、プロジェクトフォルダに `examples/astro` を指定して保存します。実行内容は `node --run build` です。実行ファイルが見つからない場合は `node` の絶対パスを設定してください。

メモとHTML出力先を選んで「サイトをビルド」を押すと、Astroの実行ログが下部に流れます。「ビルドを中止」で実行中のプロセスを停止できます。タイムアウトは初期値600秒です。

### 他のツールを接続する

実行ファイル、引数（1行1引数）、作業ディレクトリとなるプロジェクトを指定します。シェル構文は自動解釈しません。`npm.cmd` のようなバッチファイルを直接実行する代わりに、Node.jsの `--run` など実行可能なプログラムを指定してください。複数の処理を行う場合は、自分のプロジェクトのビルドスクリプトにまとめます。

外部ツールは次の環境変数を使うように設定してください。

| 値 | 内容 |
| --- | --- |
| `TATAMI_CONTENT_DIR` | 公開ノートだけを入れた一時Markdownフォルダ |
| `TATAMI_OUTPUT_DIR` | HTML・CSSなどを書き出す一時出力フォルダ |

引数内の `{content}` と `{output}` も、それぞれの一時フォルダに置換されます。空白のあるパスも1つの引数として渡すため、手動で引用符を付ける必要はありません。

`publish: true` の判定と `:::private` の除去はTatami側で先に行います。公開用Markdownはslugをファイル名として書き出し、独自のFront Matterを維持します。通常の生成処理では元のノートを変更しません。画像の自動コピーは行いません。

外部ツールは指定された公開用Markdownを読み、一時出力先へ静的HTMLを生成する必要があります。既存プロジェクトをそのまま指定しただけでは、この接続設定は自動では行われません。元の非公開ノートを別途読み込む設定にはしないでください。

終了コードが0でHTMLが生成された場合だけ、Tatamiが成果物を最終出力先へ反映します。失敗・中止・タイムアウト時は前回の公開出力を保持します。内蔵／外部ビルダーで同じ生成物管理を利用し、手動編集済み・管理対象外のファイルは上書きしません。

外部コマンドはユーザーの権限で実行するため、信頼できるプロジェクトを指定してください。Tatamiはコマンド自体をサンドボックス化しません。外部ツールが一時出力先を無視して別の場所を書き換える動作までは保護できません。HTMLの安全性は外部ビルダー側の責任です（付属Astroサンプルはサニタイズを設定済み）。

### 外部ビルドのプレビュー

アプリ内プレビューは127.0.0.1の一時ポートでHTTP配信します。Astroの `/_astro/...` のCSS・JSやディレクトリ形式のURLにも対応し、Tatamiが管理する生成物だけを配信します。外部ネットワークには公開しません。アプリ終了時にサーバーを停止します。

プレビューにはASP.NET Core 10ランタイムを使用します。.NET 10 SDKには含まれています。生成HTMLを通常のブラウザで確認する場合も、外部ビルダーがルート基準のパスを生成する場合はHTTPサーバーを使ってください。SSR、開発サーバーの常駐起動、自動デプロイは今回の対象外です。
