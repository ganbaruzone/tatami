# Tatamiでメモを書き、Webサイトを作る

Tatamiは、Markdownを編集して、公開対象のメモを静的HTMLに変換するデスクトップアプリです。このガイド自身もTatamiでビルドできます。

## 1. 起動する

.NET 10 SDKを用意し、リポジトリで次を実行します。

```sh
cd /path/to/tatami
dotnet run --project Tatami.csproj
```

## 2. メモとHTMLの保存場所を別々に選ぶ

左側の「メモのディレクトリ…」からMarkdownを保存したフォルダを選びます。「HTML出力先…」から、生成するHTMLを置く別のフォルダを選びます。初回の出力先は空のフォルダを推奨します。

```text
workspace/
├── notes/          ← メモのディレクトリ
│   └── usage.md
└── site-output/    ← HTML出力先
    ├── tatami-guide/
    │   └── index.html
    └── style.css
```

2つの設定は個別に変更でき、アプリを再起動しても記憶されます。メモのフォルダを変えても出力先は自動変更されません。ビルド前に左側の表示を確認してください。

設定はOSのユーザー別アプリデータ領域にある `Tatami/workspace.json` にJSONで保存されます。メモのファイルには設定を書き込みません。出力先にメモと同じ場所やその親は指定できません。

## 3. Markdownを編集・保存する

左側の一覧から `.md` ファイルを選び、右側で編集します。行番号、Markdownの簡易色分け、折り返しに対応しています。

| 操作 | macOS | Windows / Linux |
| --- | --- | --- |
| 保存 | ⌘S | Ctrl+S |
| 検索 | ⌘F | Ctrl+F |
| ファイル名で開く | ⌘P | Ctrl+P |
| ノートリンクを挿入 | ⌘K | Ctrl+K |
| ノート全体を検索 | ⌘⇧F | Ctrl+Shift+F |
| 元に戻す | ⌘Z | Ctrl+Z |

未保存の変更はタブとタイトルの「●」で表示します。タブ切替では編集内容を保持します。タブを閉じる時はそのタブについて保存・破棄・キャンセルを選べます。メモフォルダを切り替えるときやアプリ終了時は、未保存のタブをまとめて確認します。外部アプリで同じファイルが変更された場合は、上書きせず下のパネルにエラーを表示します。

下部パネルには保存結果、ビルド結果、エラーを表示します。ペインの境界はドラッグで調整できます。一覧の「↻」はディスク上のファイル一覧を更新します。

## ノートの作成・名前変更・ゴミ箱

- 左側の「＋ 新規」（⌘N / Ctrl+N）で、選択フォルダにMarkdownを作成します。ファイル選択中はその親フォルダに作成します。新規ノートは `publish: false` です。
- 「名前変更」は編集中のファイル名を変更します。未保存の本文とUndo履歴を保持し、同名ファイルは上書きしません。
- 「ゴミ箱へ」で編集中のノートを移動します。未保存の場合は保存・破棄・キャンセルを選びます。
- 「復元」から元の場所に戻せます。同名ファイルがある場合は上書きせず中止するので、既存ファイルを名前変更してから復元してください。

## ノート間リンク

- 左側の「リンク挿入」または⌘K／Ctrl+Kで、ノート名または見出しを検索して標準Markdownの相対リンクを挿入します。選択中のテキストはリンクラベルとして使われます。
- 「新しいノートを作成…」からリンク先ノートを作れます。ノート名を変更すると、ワークスペース内のMarkdownリンク参照も更新されます。
- 「被リンク・言及」では、開いているノートを参照するリンクと、リンクになっていないタイトル／ファイル名の言及を一覧表示します。選択すると該当ノートの行を開きます。移動・名前変更時は相対リンクを更新します。
- 「リンク切れ」で存在しないノートや見出しへのリンクを確認し、選択した結果から参照元を開けます。
- HTMLプレビューとサイト出力では、公開ノートへの `.md` リンクを生成されたHTMLページのURLへ変換します。Markdownファイル内では標準の相対リンクを維持します。

## 添付ファイル

「画像・添付ファイルを取り込む」から画像、PDF、音声、動画を選ぶと、ノート内に相対Markdownリンクを挿入し、ファイルをワークスペースの `.tatami-assets/` へコピーします。対応拡張子は PNG/JPEG/GIF/WebP/AVIF/BMP、PDF、MP3/WAV/OGG、MP4/WebM、サイズ上限は100 MBです。上限超過または非対応形式は取り込めません。

HTMLプレビューでは、現在のノートの公開本文から参照された添付だけを一時的なループバック配信で表示します。サイトビルドでは、公開ノートから参照される添付を `assets/` へコピーします。非公開ノート、`::: private` 内だけで使われるファイル、どこからも参照されないファイルは出力されません。参照されたファイルが見つからない場合は、ビルドを中止して既存のサイト出力を保持します。

`.tatami-assets/` はノート一覧やビルド入力から除外されます。Gitで管理する場合は、別ワークスペースでもこのフォルダを除外してください。標準Markdownの相対リンクなので、他のMarkdownツールでもリンクを保てます。

ゴミ箱はOSのゴミ箱とは別の、メモフォルダ内の `.tatami-trash/` です。一覧とビルド対象から除外します。完全削除機能はありません。リポジトリのGit除外設定に追加済みですが、別のGit管理メモフォルダでも `.tatami-trash/` を除外してください。公開済みHTMLから記事を取り除くには、移動後に再ビルドを成功させてください。

## 4. 公開するメモを指定する

メモの先頭にYAML Front Matterを書きます。

```markdown
---
title: はじめての記事
date: 2026-11-22
tags: [日記, Tatami]
publish: true
slug: first-post
---

# 今日のこと

この段落は公開されます。
```

**ノート全体は `publish: true` の場合だけ公開します。** `publish: false`、指定なし、Front Matterなしのノートは非公開です。

内蔵ビルダーは公開記事一覧、タグ別ページ、年別アーカイブを生成します。`SiteConfig` JSONの`archives`で一覧パス、タグ／日付ページのディレクトリ、並び順を設定できます。

編集画面上部の「公開」チェックで公開状態を設定し、「タイトル」にページタイトル、「slug」に公開URLを入力します。「適用」を押すとFront Matterに反映され、保存またはビルド時にも保留中の設定が反映されます。タイトルを空にするとファイル名が表示され、slugを空にするとファイル名からURLを生成します。slugには日本語・数字・ハイフン・アンダースコアを使えます。

`slug` はURLの識別子です。未指定ならファイル名から生成します。日本語・数字・ハイフン・アンダースコアを使えます。同じslugがある場合や、不正なパスを含む場合はビルドエラーになります。

## 5. 一部の文章・段落だけを公開しない

公開対象ノートの本文は、デフォルトですべてHTMLに含まれます。公開したくない段落は、独立した行の `:::private` と `:::` で囲みます。

```markdown
この文章は公開されます。

:::private
これは自分専用のメモです。

複数の段落や箇条書きもまとめて除外できます。
- 公開前の確認事項
- 内部用の補足
:::

この文章も公開されます。
```

囲まれた文章は元のMarkdownには残りますが、HTMLのソースにもコメントにも出力しません。閉じる `:::` を忘れるとビルドエラーになります。囲みは行単位の段落用です。文章の途中だけを除く場合は、その文章を独立した段落にしてください。

コードブロック内に書いた記法の説明は除外されません。このページの上のサンプルも、そのためHTMLに表示されます。非公開ノートの公開条件を変更する機能ではありません。

:::private
TATAMI_PRIVATE_DEMO_DO_NOT_EXPORT
この実例の段落はMarkdownにだけ残り、ビルド後のHTMLには含まれません。
:::

この行は非公開ブロックの後にあるため、HTMLにも表示されます。

## 6. ビルドしてアプリ内で見る

1. 左側のメモの場所とHTML出力先を確認します。
2. 「▷ サイトをビルド」を押します。
3. 現在の編集バッファを保存した後、公開ノートのHTMLとCSSを生成します。
4. 成功するとアプリ内のHTMLプレビューへ切り替わります。
5. 上部の選択欄で生成した記事を切り替えられます。
6. 「編集 / HTML」でエディタに戻れます。

プレビューは**最後にビルドしたHTML**を表示します。編集内容を反映するには再ビルドしてください。プレビューの「↻」は保存済みのHTMLを読み直す操作で、Markdownの再ビルドは行いません。

アプリ内プレビューでは出力先のHTMLを表示します。外部サイトや出力先以外への移動は制限しています。HTML自体は通常のブラウザでも開けます。内蔵ビルダーのCSSは相対パス参照なので、ローカルファイルとして開けます。外部ビルダーについては後述のHTTPプレビューを使用してください。

## 7. 生成物と安全な更新

出力先の `.tatami-manifest.json` は生成ファイルの管理に使います。削除・編集しないでください。Tatamiは出力先全体を消さず、自分が生成したファイルだけを更新します。公開を解除した記事のHTMLは、次回の成功したビルドで削除されます。

手動編集された生成物や同名の別ファイルがある場合は、上書きせず停止します。失敗したビルドでは以前の公開HTMLが残ることがあるため、非公開化のときもビルド成功を確認してください。

Gitで管理する場合は、出力フォルダを `.gitignore` に追加してください。リポジトリ直下の `site-output/` はすでに除外されています。

## 現時点の範囲

- 複数のMarkdownをタブで開けます。各タブは本文・Undo履歴・カーソル位置を保持します。タブを切り替えても未保存内容は残り、タブを閉じる時に保存・破棄・キャンセルを選べます。ウィンドウ終了時やメモフォルダ変更時は、未保存タブをまとめて確認します。ビルドは変更済みのタブをすべて保存してから実行します。
- 未保存の編集内容は約5秒ごとにユーザーデータ領域のTatami自動退避ファイルへ保存されます。次回起動時に復元・破棄・後で決めるを選べます。複数タブ、カーソル位置、未適用の公開設定も退避対象です。通常保存または破棄後は退避データを整理します。復元後、最後に退避した時点からノート本体が外部変更されている場合、上書き保存は競合エラーになります。
- ⌘P／Ctrl+Pでファイル名や相対パスを絞り込み、Enterで開けます。⌘⇧F／Ctrl+Shift+FではMarkdown本文を横断検索し、結果から該当行へ移動します。本文検索には開いている未保存タブの内容も含みます。
- ツールバーの「ノート一覧…」では、タグ・公開状態・日付範囲・フォルダを指定して絞り込み、日付・タイトル・パスで並べ替えられます。「条件を保存」で名前を付けて保存し、保存済み一覧から再利用できます。一覧・表・カードを切り替えて結果を確認し、選択したノートを開けます。保存した条件はワークスペースごとにユーザーデータ領域へ保存されます。
- 「新規」を選ぶと、空のノート・記事・議事録・日報のひな形を選択できます。タイトルと日付をFront Matterと本文に展開し、作成したノートは非公開で始まります。
- 編集行の先頭で `/` を入力するとコマンド候補が開きます。検索語を入力して候補を絞り、上下キーとEnterで挿入できます。図（Mermaid）、非公開エリア、画像の取り込み、表、コードブロック、見出しに対応します。図や囲みのサンプル文字列は挿入時に選択され、すぐに置き換えられます。Escapeでメニューだけを閉じます。
- 添付ファイルは`.tatami-assets/`へ取り込まれ、公開本文から参照されたものだけを出力します。
- 生HTMLは無効化しています。
- 記事一覧、タグページ、RSS、Obsidian形式の `[[ノート名]]`、自動デプロイは未実装です。
- プレビューにはOSのWebViewを利用します。WindowsではWebView2、Linuxでは対応するWebKit環境が必要です。macOSでは標準のWebKitを利用します。
- 強制終了や電源断に対するサイト全体の完全なトランザクションはありません。同じ出力先を複数のプロセスから同時に変更しないでください。

## 8. 外部ビルダーを使う

左側の「ビルダー設定…」から「Tatami 内蔵」または「外部コマンド」を選べます。既存の設定は内蔵ビルダーとして読み込まれます。切り替えてもメモのディレクトリとHTML出力先は維持します。

### ツールを接続する

外部ビルダーはTatamiに同梱していません。使いたい静的サイト生成ツールを別途インストールし、そのプロジェクトを用意してください。

1. 外部プロジェクトのビルドコマンドが、HTMLを指定ディレクトリへ出力できることを確認します。
2. Tatamiの「ビルダー設定…」で「外部コマンド」を選び、プロジェクトフォルダ、実行ファイル、引数、タイムアウトを設定します。
3. Node.jsの `node --run build` を使う場合は「Node.jsのビルド設定を入力」を押し、プロジェクトに `build` スクリプトがあることを確認します。
4. 保存後、CLIが使える場合は `tatami doctor`（別設定なら `tatami doctor --config <file>`）で確認し、`tatami build` を実行します。GUIでは「サイトをビルド」を押します。

CLIで設定する場合は、作業ディレクトリからの相対パスを使えます。

```sh
tatami config set builder external
tatami config set external.project ./my-site
tatami config set external.executable node
tatami config set external.arguments '["--run","build"]'
tatami config set external.timeout 600
tatami doctor
tatami build --json
```

実行ファイル、引数（1行1引数）、作業ディレクトリとなるプロジェクトを指定します。シェル構文は自動解釈しません。`npm.cmd` のようなバッチファイルを直接実行する代わりに、実行可能なプログラムを指定してください。複数の処理を行う場合は、自分のプロジェクトのビルドスクリプトにまとめます。

外部ツールは次の環境変数を使うように設定してください。

| 値 | 内容 |
| --- | --- |
| `TATAMI_CONTENT_DIR` | 公開ノートだけを入れた一時Markdownフォルダ |
| `TATAMI_OUTPUT_DIR` | HTML・CSSなどを書き出す一時出力フォルダ |

引数内の `{content}` と `{output}` も、それぞれの一時フォルダに置換されます。空白のあるパスも1つの引数として渡すため、手動で引用符を付ける必要はありません。

`publish: true` の判定と `:::private` の除去はTatami側で先に行います。公開用Markdownはslugをファイル名として書き出し、独自のFront Matterを維持します。添付は公開ノートの公開本文から参照されたものだけを成果物へ追加し、Markdown内の添付リンクを生成先の相対URLへ変換します。通常の生成処理では元のノートを変更しません。

外部ツールは指定された公開用Markdownを読み、一時出力先へ静的HTMLを生成する必要があります。既存プロジェクトをそのまま指定しただけでは、この接続設定は自動では行われません。元の非公開ノートを別途読み込む設定にはしないでください。

終了コードが0でHTMLが生成された場合だけ、Tatamiが成果物を最終出力先へ反映します。失敗・中止・タイムアウト時は前回の公開出力を保持します。内蔵／外部ビルダーで同じ生成物管理を利用し、手動編集済み・管理対象外のファイルは上書きしません。

外部コマンドはユーザーの権限で実行するため、信頼できるプロジェクトを指定してください。Tatamiはコマンド自体をサンドボックス化しません。外部ツールが一時出力先を無視して別の場所を書き換える動作までは保護できません。HTMLの安全性は外部ビルダー側の責任です。

### 設定を診断する

`tatami doctor` は.NET SDK、設定ファイル、入力・出力パス、選択中のビルダーを確認します。外部ビルダー選択中は、実行ファイルへ5秒以内の `--version` 呼び出しを行い、プロジェクトフォルダとタイムアウト値も確認します。診断行は標準エラーに出て、問題が一つでもある場合は終了コード1になります。設定パスを明示する場合は `tatami doctor --config ./tatami.json` のように指定してください。

`tatami doctor --fix` は、設定に入力・出力先が指定されている場合に限り、不足ディレクトリを作成します。入力・出力先が重なるなど安全性を確認できない場合は作成しません。外部プロジェクトの `package-lock.json`、`yarn.lock`、`pnpm-lock.yaml` に応じた依存導入コマンドを表示しますが、自動実行はしません。表示内容を確認してからプロジェクトで実行してください。設定がない場合はパスを推測せず、`tatami config set` または `--config` を案内します。

| 表示 | 確認すること |
| --- | --- |
| 外部ビルダー実行ファイルがNG | 実行ファイル名がPATH上にあるか、または実行ファイルの絶対パスか確認します。`--version` をサポートしないコマンドは、この項目がNGでも実ビルドは動作する場合があります。 |
| 外部ビルダープロジェクトがNG | `external.project` が存在するローカルのプロジェクトフォルダか確認します。相対パスはCLIの作業ディレクトリ基準です。 |
| 入力パスがNG | ノートフォルダが存在するか、`input` 設定を確認します。 |
| 出力パスがNG | 空欄でないこと、入力フォルダと同じ場所またはその親でないことを確認します。入力フォルダ内の出力先は使用できます。 |
| 入力と外部プロジェクトがNG | ノートフォルダと外部ビルダーのプロジェクトフォルダを別にします。 |
| 出力先と外部プロジェクトがNG | 出力先を外部プロジェクトと別のフォルダにし、外部プロジェクトの親フォルダを出力先にしないでください。 |
| ビルドでHTMLがない | 外部コマンドが `TATAMI_OUTPUT_DIR`（または `{output}` 引数）へ `.html` ファイルを書き出すか確認します。 |

`doctor` は外部ビルダー固有の設定までは変更・検証しません。依存パッケージの導入は `--fix` が表示したコマンドを確認して実行してください。

### 外部ビルドのプレビュー

アプリ内プレビューは127.0.0.1の一時ポートでHTTP配信します。ルート相対のCSS・JSやディレクトリ形式のURLに対応し、Tatamiが管理する生成物だけを配信します。編集画面からプレビューを開くと現在の記事を未保存の本文・メタデータから描画し、入力後約350ミリ秒で表示を更新します。プレビューのページ一覧から別の記事を選ぶと、ビルド済みHTMLを表示します。外部ネットワークには公開しません。アプリ終了時にサーバーを停止します。

プレビューにはASP.NET Core 10ランタイムを使用します。.NET 10 SDKには含まれています。生成HTMLを通常のブラウザで確認する場合も、外部ビルダーがルート基準のパスを生成する場合はHTTPサーバーを使ってください。SSR、開発サーバーの常駐起動、自動デプロイは今回の対象外です。

### 外部変更の確認とビルドエラーの移動

開いているノートは約2秒ごとにディスク上の内容を確認します。外部変更を検知すると「外部変更を確認」ボタンが表示され、差分を見て編集を続けるかディスク版へ置き換えられます。置き換えは未保存の編集を破棄するため、ダイアログに確認を表示します。保存時にも外部変更との競合を検査し、変更されたファイルを誤って上書きしません。

ビルド出力に `.md` ファイルと行番号を含む診断がある場合、「エラー位置」から対象ファイルを開いて該当行へ移動できます。対応する出力形式は `path.md(line,column)` と `path.md:line:column` です。

## 9. CLIを使う

CLIはGUIを開かず、ノート確認・変更とサイトビルドを実行します。.NET 10 SDKがあるリポジトリでは、そのまま起動できます。

```sh
dotnet run --project Tatami.Cli -- --help
dotnet run --project Tatami.Cli -- notes list --input ./notes
dotnet run --project Tatami.Cli -- notes validate --input ./notes
dotnet run --project Tatami.Cli -- notes search "静的サイト" --input ./notes
dotnet run --project Tatami.Cli -- notes metadata set welcome.md publish true --input ./notes
dotnet run --project Tatami.Cli -- build --input ./notes --output ./site-output --json
dotnet run --project Tatami.Cli -- preview --output ./site-output
dotnet run --project Tatami.Cli -- build --watch --input ./notes --output ./site-output
```

`tatami` 実行ファイルを発行するには、プロジェクトルートで次を実行します。

```sh
dotnet publish Tatami.Cli/Tatami.Cli.csproj -c Release -o ./artifacts/tatami
./artifacts/tatami/tatami --help
```

発行物はframework-dependentです。実行先に.NET 10ランタイムを用意し、`tatami` 実行ファイルをPATH上の場所へ置いてください。

| コマンド | 用途 |
| --- | --- |
| `tatami --help` / `--version` | ヘルプ・バージョン |
| `tatami build` | 内蔵または設定済み外部ビルダーで生成。`--input`、`--output`、`--config`、`--json` に対応 |
| `tatami build --watch` | 初回ビルド後、Markdown変更を検出して再ビルド。Ctrl+Cで終了 |
| `tatami preview` | 生成済みHTMLを127.0.0.1で配信し、Ctrl+Cで終了。`--output` または設定済み出力先を使用 |
| `tatami notes list` / `show <path>` | ノート一覧・Front Matterと公開判定 |
| `tatami notes validate` | 出力を変更せずFront Matter、公開slug重複、公開本文の非公開ブロックを検査 |
| `tatami notes search <query>` | ファイル名・タイトル・タグ・本文を検索し、本文は相対パスと行番号を表示 |
| `tatami notes metadata set <path> <key> <value>` | `title`、`publish`、`slug` を変更し、他のFront Matter項目は保持 |
| `tatami notes create <name>` | 非公開ノート作成。`--directory` で作成先を指定 |
| `tatami notes rename <path> <name>` | ノート名変更 |
| `tatami notes trash <path>` / `trash list` / `restore <id>` | アプリ内ゴミ箱への移動・一覧・復元 |
| `tatami config show` / `set <key> <value>` | 設定確認・変更。外部設定キーは `external.project`、`external.executable`、`external.arguments`、`external.timeout` |
| `tatami doctor` | .NET、設定、パス、外部ビルダー診断 |

入力・出力の相対パスは作業ディレクトリ基準です。`--input` や `--output` を省略すると、`--config <file>` またはアプリのユーザー設定を読みます。通常結果は標準出力、エラーと診断は標準エラーです。`--quiet` は補助メッセージを抑制し、`--verbose` は追加情報を表示します。終了コードは成功0、引数・入力エラー2、実行時エラー1です。`build --json` は成功・失敗、公開／非公開件数、出力先をJSONで標準出力へ返します。
